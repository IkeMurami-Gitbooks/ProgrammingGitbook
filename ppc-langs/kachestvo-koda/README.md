# Качество кода

Качество кода — это несколько разных вещей: код должен правильно работать, быть понятным, безопасным, удобным для изменения и предсказуемым в эксплуатации.

| Категория                           | Для чего нужна                                                               | Что обычно настраивают                                                                         |
| ----------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Форматирование                      | Единообразное оформление                                                     | Отступы, переносы, длину строк, правила автоматического форматирования                         |
| Линтинг                             | Поиск типичных ошибок и нежелательных конструкций                            | Набор правил, строгость, допустимые исключения, автоматические исправления                     |
| Проверка типов и статический анализ | Поиск несогласованностей без запуска программы                               | Строгость проверок, обработку отсутствующих значений, требования к контрактам, области анализа |
| Автоматические тесты                | Проверка поведения программы                                                 | Какие сценарии проверять, уровни тестов, окружения, запуск и критерии успешности               |
| Архитектурные ограничения           | Сохранение понятной структуры системы                                        | Границы модулей, разрешённые зависимости, запрет циклов, правила доступа к внутренним деталям  |
| Анализ безопасности                 | Поиск опасных способов обработки данных и использования возможностей системы | Проверки уязвимых конструкций, утечек секретов, правила обработки результатов                  |
| Контроль зависимостей               | Управление рисками стороннего кода                                           | Фиксацию версий, обновления, проверку уязвимостей и лицензий, допустимые источники             |
| Проверки производительности         | Выявление замедлений и чрезмерного потребления ресурсов                      | Измеряемые сценарии, допустимые задержки, потребление памяти и другие ограничения              |
| Сборка и воспроизводимость          | Получение предсказуемого результата из исходников                            | Версии среды и зависимостей, команды сборки, конфигурацию, сборку из чистого окружения         |
| Документация и контракты            | Передача знаний о назначении и использовании кода                            | Требования к описанию интерфейсов, настройке проекта, примерам и архитектурным решениям        |
| Ревью изменений                     | Оценка решений, которые плохо проверяются автоматически                      | Кто проверяет изменения, что проверяет, когда нужно дополнительное согласование                |
| Наблюдаемость и эксплуатация        | Обнаружение проблем при реальной работе                                      | Логи, метрики, трассировку, оповещения, диагностику и обработку сбоев                          |
